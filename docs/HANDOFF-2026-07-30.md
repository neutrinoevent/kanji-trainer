## 2. The load-bearing ideas

If you change nothing else, understand these five.

**Scopes are the spine.** A scope is `null` (everything), `{cid, from, to}` (a
built-in track, optionally a batch range), or `{list: id}` (a user list). Review,
drill, the eight games, and the mastery exam all take one. Adding a new
kanji-asking surface means giving it a scope and carrying that scope in every
route into it. **Three separate bugs have come from forgetting this** (V-005,
V-008, and the Path which is still open).

**Fluency is demonstrated, not waited out.** `demo_tier()` in `server.py`
computes a card's tier from the review log: distinct question types answered on
target, at least one *produced from memory*, a minimum count, across distinct
days, at accuracy. Scheduling intervals do not enter into it. See V-006/V-007.

**"Correct" and "on target" are different.** Typing a real but secondary meaning
is accepted (marking "big" wrong for 大 would be a false negative) but does not
count toward demonstrating the primary sense. The `on_target` column carries it.

**Don't trust, measure.** Typeface variety fingerprints each candidate face and
drops any that renders identically to another, because CSS falls back silently
(V-009). Games refuse to silently substitute kanji from outside a scope (V-008).
The same instinct applies to anything that *appears* to work.

**Progress must be visible while it's being made.** A number that can't move
during a session teaches the learner that effort is invisible (V-007). Keep bars
strict; keep the distance to them legible.

## 3. Conventions

- **`VISION.md` is append-only.** Numbered entries with the idea, the audit, the
  decisions *and their reasoning*, what shipped, what was deliberately skipped.
  Revisions go **underneath** the original (see "D3 revised"), never replacing it.
- **`docs/IDEAS.md`** is the running idea list — add to it as things come up
  rather than carrying them in conversation.
- **`docs/KNOWN-ISSUES.md`** includes a *"not issues, don't fix these by
  mistake"* section for deliberate choices. Read it before "fixing" anything.
- **Commits: sole author `neutrinoevent`**, no `Co-Authored-By`, no "Generated
  with", no mention of any AI tool anywhere in the repo. Verified clean across
  all history. Alexander attributes the collaboration himself.
- **Commit messages are prose paragraphs** explaining reasoning and rejected
  alternatives, not bullet lists.
- **Delete `data/trainer.db*` before every commit** so the repo ships clean and
  first-run flows stay testable.

## 4. How to test

Run `python3 server.py 7791` in the background, curl the API, then drive the UI
over CDP: chromium at
`~/Library/Caches/ms-playwright/chromium_headless_shell-1228/chrome-headless-shell-mac-x64/chrome-headless-shell`
with `--remote-debugging-port=9222`, plus Node's native `WebSocket`. Write `.mjs`
driver files to a scratch dir — heredocs mangle `${}` in JS template literals.
Screenshot and actually look at the images.

**Test the thing, not the appearance of the thing.** Two examples worth copying:
the typeface work pixel-hashes glyphs rather than trusting font names, and the
exam's marking was extracted into a pure `scoreExam()` so thresholds could be
checked without a browser. Both caught real problems.

**Watch for test rot.** Two known-stale assertions exist: `game:odd` "fails"
because Odd One Out now correctly declines narrow scopes, and one driver depended
on a `__lastSess` hook that was removed. Don't chase them.
